Рабочие инструменты

Инструменты выполняются на устройстве пользователя. Для тяжёлого аудио/видео первый запуск загружает FFmpeg WebAssembly.

MEDIA ENGINE

Аудио и видео

Конвертация популярных медиаформатов, извлечение аудио и GIF. Подходит для небольших и средних файлов; предел определяется памятью браузера.

Файл не выбран
Выберите файл.
Для очень больших видео браузер может закончить оперативную память. Это ограничение статического GitHub Pages/WASM, а не вашего файла.
IMAGE

Изображения

JPG, PNG, WebP: формат, качество и размер. Всё через Canvas API без отправки изображения на сервер.

Если размеры пустые — сохраняется исходное разрешение.
SPREADSHEET

Excel / CSV / ODS

XLSX, XLS, XLSB, ODS, CSV и TSV. Можно конвертировать книгу или выгрузить первый лист в CSV.

Сложные макросы и часть форматирования при смене формата не сохраняются.
DATA

CSV ↔ JSON

Преобразование структурированных данных через SheetJS: CSV в JSON и JSON-массив обратно в CSV.

UTF‑8, без отправки данных.
PDF LAB

PDF: объединить или разделить

Объединяйте несколько PDF в один или разбивайте PDF на отдельные страницы. Работает через PDF-Lib.

Файлы не выбраны
Защищённые паролем PDF могут не открыться.
ZIP

Создать ZIP

Упаковать несколько файлов в ZIP прямо в браузере. Подходит для отправки набора файлов одним архивом.

Файлы не выбраны.
UNZIP

Открыть ZIP

Посмотреть содержимое ZIP и скачать отдельные файлы без загрузки архива на сервер.

TEXT

Текстовые файлы

TXT, MD, JSON, XML, HTML, LOG, YAML/INI. Открыть в UTF‑8, отредактировать и сохранить с новым расширением.

Для JSON выполняется проверка и форматирование.
BASE64

Файл ↔ Base64

Кодировать файл в Data URL/Base64 или декодировать строку Base64 обратно в файл.

CHECKSUM

SHA‑256 / SHA‑1 / SHA‑512

Посчитать контрольную сумму файла через Web Crypto API — удобно для проверки целостности загрузок.

FAQ

Как это устроено

Почему GitHub Pages хватает для этого сайта?

GitHub Pages отдаёт статические HTML/CSS/JS-файлы. Тяжёлая работа выполняется не на GitHub, а непосредственно в браузере пользователя через WebAssembly и Web APIs. Поэтому сервер для большинства инструментов не нужен.

Файлы загружаются куда-нибудь?

Текущие браузерные инструменты обрабатывают данные локально. Внешние CDN загружают только библиотеки кода — не ваши выбранные файлы. Отдельная отправка по почте происходит только если пользователь сам выбирает ручную услугу.

Почему нельзя гарантировать конвертацию огромного видео?

FFmpeg WebAssembly использует память браузера. На мобильном устройстве или при гигабайтных роликах память может закончиться. Для такого режима уже нужен backend с обычным FFmpeg.

Почему DJVU, DWG и KiCad не конвертируются одной кнопкой?

Для них нужны специализированные движки и контроль корректности результата. Делать кнопку, которая лишь меняет расширение или выдаёт повреждённый файл, хуже, чем честно обозначить ограничение.

Редкий формат?

Напиши, из какого формата в какой нужен результат. DJVU, CAD, электронные схемы, книги и нестандартные файлы можно вынести в следующий серверный модуль.
